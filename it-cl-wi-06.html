IT-CL-WI-06: Validate Cloud Identity and Access Controls

Provides a repeatable method to validate cloud workload identity and access controls across AWS and Azure, including privileged access, workload identities and evidence requirements.

Work InstructionAWSAzureIdentity and Access

📌 Version: v1.0
👤 Owner: Cyber Security / Cloud Platform Teams
📅 Published: 19 Sep 2026
Live
Objective
Validate Identity and Access controls

This work instruction provides evidence-based validation steps for AWS and Azure. It should be used during initial baseline assessment, quarterly control review, major cloud changes and after material incidents.

AWS examples: IAM Identity Center, IAM roles, STS, CloudTrail, Access Analyzer
Azure examples: Entra ID, PIM, Azure RBAC, managed identities, Activity Logs
Steps
Validation procedure
Step 1: Inventory privileged identities

Export privileged users, roles, service principals, workload identities and emergency accounts from both clouds.

Step 2: Validate federation and MFA

Confirm human access uses federated identity and MFA; record exclusions and break-glass exceptions.

Step 3: Validate privileged access model

Check time-bound approval, logging, review cadence and permanent administrator assignments.

Step 4: Validate workload identities

Confirm managed or temporary credentials are used and static credentials are avoided or formally accepted.

Step 5: Record evidence and gaps

Update the workbook with evidence links, status, score, gaps, treatment and risk mapping.

Evidence
Minimum evidence set
  • Configuration export or screenshot showing the relevant setting.
  • Evidence link or file reference recorded in the workbook evidence log.
  • Owner, review date, reviewer decision and any remediation ticket.
  • Exception or risk acceptance record where the baseline is not met.
