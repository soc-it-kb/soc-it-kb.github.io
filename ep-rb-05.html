EP-RB-05: Investigate Mimikatz / Credential Dumping Detection

Runbook for validating and scoping Mimikatz or equivalent credential dumping detections, including LSASS access analysis, account exposure assessment, and escalation decisions.

Section 1
Purpose

Guide SOC analysts through initial validation and investigation of Mimikatz, LSASS access, and related credential dumping detections. This runbook determines whether the event is a false positive, blocked attempt, successful credential exposure, or part of a wider intrusion.

Section 2
Inputs required
  • Alert ID, host name, user, timestamp, process name, process path, hash, parent process, and command line.
  • EDR process tree, file events, registry events, network connections, and containment status.
  • Identity logs for affected user and any privileged sessions on the host.
  • Recent local administrator activity, remote logons, service creations, scheduled tasks, and lateral movement indicators.
Section 3
Triage decision flow
1
Confirm detection credibility. Review whether the alert fired on a known malicious file, suspicious command line, LSASS memory access, dump file creation, or behavioural model.
Do not rely only on the detection name; validate the underlying behaviour.
2
Determine LSASS access outcome. Establish whether access was attempted, blocked, successful, or followed by dump/archive/file-write activity.
3
Identify the execution context. Check user privilege, session type, source logon, parent process, working directory, and whether the process ran from a user-writable path.
4
Check credential exposure. Identify accounts with active logon sessions on the host, including privileged, service, cached, RDP, and administrative sessions.
5
Scope the estate. Search for matching hashes, filenames, command-line fragments, dump file patterns, and equivalent LSASS access events across endpoints and servers.
6
Escalate according to decision outcome. Escalate to EP-PB-06 for credible or confirmed credential dumping, and to ID playbooks if account misuse is detected.

Section 5
Decision outcomes

False positive / expected admin activity

  • Known approved security or forensic tool.
  • Change ticket or maintenance window exists.
  • No suspicious parent chain, dump, or lateral activity.

Confirmed incident

  • Unapproved LSASS access or dump activity.
  • Mimikatz-like strings or credential theft behaviour.
  • Privileged exposure or lateral movement indicators.

Escalate immediately if the affected host is a domain controller, PAW, server, jump host, backup server, hypervisor management host, or if a privileged account had an active session.
